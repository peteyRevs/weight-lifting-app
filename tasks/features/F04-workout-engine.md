## Goal
One pure reducer, shared by phone and watch, turns an append-only log of `WorkoutEvent`s into `WorkoutState` deterministically, so two devices holding the same envelopes always agree, mid-workout crashes resume by replay, and every UI is a projection. This is the core of "phone + watch share one live workout".

## User stories
- As a lifter, whatever I log on the watch appears on the phone and vice versa, in any order of arrival, with no lost sets.
- As a lifter, the rest countdown shows the same number on both wrists and pockets.

## Scope
**In:** events, envelopes, reducer, effects, replay, dedupe, convergence rules, `WorkoutEventStore` protocol, model-based tests.
**Out:** transport and actors (F17), persistence of envelopes (F05), UI (F10/F18).

public enum WorkoutEvent: Hashable, Codable, Sendable {
    case started(WorkoutState)                                            // initial snapshot from SessionBuilder (phase .live)
    case exerciseSelected(exerciseIndex: Int, setIndex: Int)
    case setLogged(exerciseIndex: Int, setID: SetID, weight: Weight, reps: Reps, at: Date)
    case setUnlogged(exerciseIndex: Int, setID: SetID)
    case setTargetChanged(exerciseIndex: Int, setID: SetID, weight: Weight?, reps: Reps?)   // nil = unchanged
    case setAdded(exerciseIndex: Int, set: LoggedSet)                    // set.id generated by the originating device; kind .added
    case allSetsRepeated(exerciseIndex: Int, weight: Weight, reps: Reps) // "Repeat last" (rule 25)
    case exerciseSwapped(exerciseIndex: Int, to: ExerciseID, name: String, alsoUpdateProgram: Bool)
    case restStarted(endsAt: Date, total: Duration)
    case restExtended(by: Duration)                                      // if no rest active → restStarted(now + by, by) (decision #7)
    case restSkipped
    case finished(at: Date)
    case discarded(at: Date)
}
public struct EventEnvelope: Hashable, Codable, Sendable, Comparable {
    public let event: WorkoutEvent; public let workoutID: WorkoutID; public let device: DeviceID; public let seq: UInt64; public let wallClock: Date
    public static func < (a: Self, b: Self) -> Bool   // (wallClock, device.rawValue.uuidString, seq)
    public var key: EnvelopeKey                        // struct EnvelopeKey: Hashable { device, seq } — dedupe key
}
public enum Effect: Hashable, Sendable {
    case haptic(Haptic)                     // enum Haptic { setLogged, restOver, personalRecord, workoutFinished }
    case scheduleRestNotification(at: Date), cancelRestNotification
    case updateLiveActivity
    case persist(EventEnvelope), transmit(EventEnvelope)
    case materialize(WorkoutSummary)        // on finished
    case discardLog
}
public enum WorkoutEngine {
    public static func reduce(_ state: WorkoutState?, _ envelope: EventEnvelope, now: Date) -> (WorkoutState?, [Effect])
    public static func replay(_ log: [EventEnvelope], now: Date) -> WorkoutState?      // sort, dedupe by key, fold; nil if no .started
    public static func summary(_ state: WorkoutState, prs: [PersonalRecord]) -> WorkoutSummary
}
public protocol WorkoutEventStore: Sendable {
    func append(_ envelopes: [EventEnvelope]) async throws                     // idempotent on key
    func envelopes(for workout: WorkoutID) async throws -> [EventEnvelope]
    func highestSeq(for workout: WorkoutID, device: DeviceID) async throws -> UInt64?
    func liveWorkoutIDs() async throws -> [WorkoutID]                            // logs with .started and no terminal event
    func compact(workout: WorkoutID) async throws
}

### Reduction rules (each is a numbered test)
1. `started` on `nil` → state; `started` on existing → ignored. Any event before `started` is buffered by `replay` ordering, never applied.
2. Terminal: after `finished`/`discarded`, every later envelope is ignored (no effects).
3. `setLogged`: sets `doneAt`, `weight`, `reps` on the set; `latest by envelope order wins` for the same set. Effects: `.haptic(.setLogged)`, `.persist`, `.transmit`, `.updateLiveActivity`. Then, if the set was not done before: (a) **rest** — if `settings.autoRest` (carried in `WorkoutState.autoRest` from the snapshot) and the logged set is `isLastOfRound` in its block (F02 `SupersetRounds`; a straight exercise is a one-member block → every set is last of round), emit `restStarted(endsAt: at + groupRest, total: groupRest)` semantics inline (state.rest set; effect `.scheduleRestNotification`); (b) **cursor** — rule 20 order: next undone ref later in `displayOrder` → else earliest undone earlier → else first set of next block → else stay.
4. `setUnlogged`: clears `doneAt`; never moves the cursor or clears rest (rule 22).
5. `setTargetChanged`: field-wise last-writer-wins by envelope order; weight clamped ≥ 0, reps ≥ 1.
6. `setAdded`: idempotent by `set.id`; appended after the exercise's last non-drop row? — no: appended at the end (rule 26); `totalSets` recomputed.
7. `allSetsRepeated`: writes weight/reps into every set of the exercise, done flags unchanged (rule 25).
8. `exerciseSwapped`: replaces `exerciseID`/`name`, keeps sets/rest/step/rpe/targets (rule 27); `alsoUpdateProgram` is passed through in `WorkoutState.programUpdates` for materialization (decision #13).
9. `restStarted`: sets `rest`; `restExtended(by:)`: `endsAt += by`, `total += by`; if `rest == nil` → `rest = RestTimer(endsAt: now + by, total: by)`; `restSkipped`: `rest = nil`, effect `.cancelRestNotification`. Rest reaching zero is not an event: views derive "over" from `endsAt <= now`; the haptic at zero is scheduled by the effect at `restStarted` time (watch) — see F18.
10. `finished`: `phase = .finished`, `endedAt`; effects `.materialize(summary)`, `.haptic(.workoutFinished)`, `.cancelRestNotification`. `discarded`: `phase = .discarded`; effects `.discardLog`, `.cancelRestNotification`.
11. `exerciseSelected`: sets cursor if the ref exists and is not done; otherwise ignored.
12. Convergence: for any multiset of envelopes, `replay` is order-independent (sorting) and duplicate-tolerant (dedupe by key). Ties on `wallClock` break by device id then seq, so two devices never disagree.

## Acceptance criteria
1. Given the 5-exercise seed session (spec §6.3) and `setLogged` for exercise 0 set 0, when reduced, then `rest.endsAt == at + 150 s`, cursor is (0, 1), effects contain `.haptic(.setLogged)` and `.scheduleRestNotification(at + 150 s)`.
2. Given a superset A(3 sets, rest 90) + B(3 sets, rest 60), when A1 is logged, then no rest starts and cursor moves to B1; when B1 is logged, then rest is 90 s and cursor is A2.
3. Given all sets of exercise 0 done, when the last is logged, then cursor is (1, 0).
4. Given a done set, when `setUnlogged` arrives, then cursor and rest are unchanged.
5. Given no active rest, when `restExtended(by: 30 s)` arrives at `now`, then `rest == RestTimer(endsAt: now + 30 s, total: 30 s)`.
6. Given `finished`, when any later envelope arrives, then state is unchanged and effects are empty.
7. Given a log of N envelopes, when shuffled 100 times, then `replay` yields identical states (Equatable) every time.
8. Given a log with every envelope duplicated, when replayed, then the state equals the deduplicated replay.
9. Given device P and device W applying disjoint local events during a partition, when each receives the other's envelopes (in any order), then both states are identical.
10. Given 1,000 random valid event sequences (seeded RNG, `LEDGER_PROPERTY_SEED_COUNT`), when reduced step-by-step and compared to `ModelOracle` (a straightforward mutable implementation of the rules), then states match at every step.
11. Given `setTargetChanged(weight: 190)` from W at t=10 and `setTargetChanged(weight: 195)` from P at t=9, then weight is 190 regardless of arrival order.
12. Given `exerciseSwapped(alsoUpdateProgram: true)`, when finished, then `summary`/state carries the program update so F05 can apply it.

## Non-functional
- `reduce` is O(sets) per event; `replay` of 500 envelopes < 5 ms on a simulator (measured test, `.slow` tag excluded from PR).
- No `Date()` inside the engine; `now` is a parameter used only for `restExtended` with no active rest.

## Risks / unknowns
- `started(WorkoutState)` snapshot size on the mirroring channel — acceptable (a few KB); F17 may compress.
- Cursor rules for exercises added mid-workout (not in scope; `setAdded` only adds sets).
