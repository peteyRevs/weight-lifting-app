(`tasks/chores/2026-10-09-pr-lane-time.md`): one `TEST_RUNNER_` variable in `pr.yml`, read by the tests, so

## The problem

On `main` the iOS test step took about 1,255–1,293 s on a developer Mac at the PR plan's 200 seeds (F10 S7's
gate of 2026-10-14: 1,267 s, 42,168 cases). The runner is 1.8–2× slower, and a PR's first run builds cold
(about 1,150 s) after about 125 s of script tests, so every first run reached the deadline, whatever its
code. With the runner's 40 seeds the same step took 903 s on the Mac (below): about 1,800 s on the runner, still
past the 1,235 s a cold run has left for tests.

## The change

`TEST_RUNNER_LEDGER_SWEEP: pr` in `Check`'s step, beside the seeds; `xcodebuild` hands it to the test runner as
`LEDGER_SWEEP`. One helper reads it: `TestSweep` in `LedgerTestSupport/Sweeps/TestSweep.swift`.

- `TestSweep.isReduced`: `LEDGER_SWEEP == "pr"`. Unset, as in the local gate, the nightly and `swift test`,
  every sweep is whole: each helper returns its input unchanged.
- `TestSweep.subset(_:keeping:)`: the whole list, or in a reduced run the elements kept, in order (the first if
  none is). A reduced list is always a subset of the whole one, so the runner can fail nothing the full gate
  passes.
- `TestSweep.sizes(_:also:)`: of a list of text sizes, the representatives `.xSmall`, `.large`, `.xxxLarge` and
  `.accessibility5`, the list's own first and last, and any `also`.

What each reduced sweep keeps, and why:

| Sweep | Whole | Under `pr` | Why these |
|---|---|---|---|

Not reduced, on purpose: appearances (light and dark) wherever colour is what is tested (the orange audits);
lists that are already a suite's chosen deciders (`DayEditorViewsLayoutAdversarialTests.sizes`, "three sizes
decide here", the boundary at `.accessibility1` included; `compactSizes`; `fewSizes`); every check over all the
sizes at once (`room_withBoldTextAndLongerWords`' least room, `TypeScaleTests`' monotonic sizes, the strip's
"targets fall short at the three smallest sizes", which asserts the whole list); controls; the UI tests; the
seeds. `TodayViewsLayoutAdversarialTests.sizes` was reduced and put back: `TodayViewsRound2AdversarialTests`
takes `Layout.sizes.prefix(7)` as "the seven standard sizes", which a reduced list breaks (a run failed on it),
and it saved about 5 s.

## The deadline

A first run: about 125 s of script tests, a cold build of 1,140–1,221 s, 10 s of catalogs and boot, then the
tests. At a 2× runner the tests take about 1,150 s, so a cold run ends at 2,437–2,508 s: inside 2,520 s by 12–83 s,
not the five minutes asked. At 1.8× (1,040 s) it ends at 2,322–2,393 s, 127–198 s inside. Before this change
the same run needed about 1,800 s of tests and could not finish. A warm run (570–750 s build) has
about 10 minutes. Options, cheapest first: (1) accept the margin and watch the first runs; (2) reduce the Day
editor's cut measure under `pr` with its control's count made lane-aware (about 10–12 s Mac, a tester's file);
(3) run the UI smoke only in the local gate (65 s Mac, about 130 s runner; a test-plan change, so not done
here); (4) 30 seeds (about 15–20 s Mac; the precedent notes no seed to spare for the HLC control); (5) a
`main` warm-up cache job, which removes the cold build from first runs (ci-cd.md, "No `main` warm-up job").

  `LEDGER_XCODEBUILD_DEADLINE: 2520`.

  runner, the step takes what it took before and the case count tells (a failed run uploads its bundle):
  `FeatureProgramTests` has 3,050 cases with every sweep and 2,555 under `pr`.
- To run what `Check` runs locally: `TEST_RUNNER_LEDGER_SWEEP=pr TEST_RUNNER_LEDGER_PROPERTY_SEED_COUNT=40

  positions or counts of a swept list (as `Layout.sizes.prefix(7)` does).
